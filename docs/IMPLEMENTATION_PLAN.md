# Moonlight Plus TV 首版实施方案

确认日期：2026-10-03。目标为第三代 Apple TV 4K、Foundation Sunshine、PS4/PS5 手柄。先跑通，再增强；由 Mac/Xcode 编译与签名，当前 Windows 工作区用于源码准备。

## 基础路线

- 以 VoidLink Integration 提交 `38e16f1ee3158c3a2c1027fc09fd01bb983b3fd6` 为基线，保留现有 TV target、Objective-C/Swift 架构、串流核心及固定子模块。
- 最低 tvOS 16.0；由于上游源码包含 SDK 26 类型，构建使用 Xcode 26 或更新版本。运行系统下限与构建 SDK 版本是不同要求。
- 显示名 Moonlight Plus；Bundle ID `com.jacob.moonlightplus.tvos`；共享 scheme `Moonlight Plus TV`。保留上游工程和内部类名，减少桥接头与资源路径风险。
- 保留 GPLv3 许可证及原始署名。采用独立图标；完成前不得将上游图标视为最终品牌资产。

## 第一阶段：构建与基础使用

1. 修复可静态确认的 SDK 路径和构建配置，加入 Debug/Release 不签名真机构建脚本与 CI。
2. 在 Mac 编译两种配置，依据实际诊断处理平台 API、依赖及资源问题。Windows 静态检查不得标记为编译通过。
3. 真机验证自动发现、手动 IP、PIN 配对、游戏列表、启动、退出、重连及信息持久化。
4. 从 1080p60/H.264/20 Mbps/SDR/立体声开始，再验证 4K60/HEVC/40 Mbps/SDR，最后独立验证 HDR。
5. 验证遥控器焦点、返回操作和 PS4/PS5 按键、摇杆、扳机、连接及重连。震动按系统实际能力启用，高级触觉与自适应扳机不作为首版要求。
6. 网络、配对、主机和解码失败提供可理解的提示及重新连接入口。

## 第二阶段：增强

- 配置预设：先审查既有机制。触控布局 profile 不等同串流预设；必要时新增独立持久化格式，包含版本、分辨率、帧率、码率、编码、HDR 与音频设置。支持保存、重命名、删除、选择。
- 初始预设为兼容 1080p60 和清晰 4K60，参数沿用第一阶段；预设只在下次启动串流时生效。
- 统计：复用实际数据源，显示帧率、码率、延迟、解码耗时与丢帧；无可靠数据的指标显示不可用。
- 快捷菜单：优先复用上游，通过遥控器返回键或手柄菜单键打开，提供统计、配置、断开与结束主机应用。结束主机应用需明确确认。
- 打开菜单时拦截导航输入，关闭时释放残留按键，再恢复游戏输入。为预设持久化和输入路由编写针对性测试。
- 独立图标及 TV 资源在第一轮构建通过后完成，并在真机确认显示正确。

## 范围与验收

Foundation Sunshine 首版走标准兼容协议。不改网络协议，不整体替换底层子模块。实时码率、显示器选择、麦克风、文件夹映射、Android 专属功能和新增插帧工作均后置。保留的上游功能不代表本项目已验证支持。

Debug/Release 干净构建通过后，在有记录的网络环境下分别进行 1080p60 与 4K60 SDR 30 分钟测试，要求无崩溃、持续黑屏或持续音画失步。HDR、手柄重连、网络中断、主机离线、配对失败、预设及信息重启保留分别验收。交付源码、构建步骤、差异清单和实际测试记录；本阶段不发布 App Store/TestFlight。
